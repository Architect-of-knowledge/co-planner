# המתכנן־השותף (co-planner)

**לתכנן עם Claude כמו עם שותף חד שקרא את כל הקוד שלכם.**

הפקודה `/co-planner` היא תוסף ל־Claude Code לתכנון כל דבר : יכולת חדשה, תחום במוצר או עיצוב מחדש. במקום תוכנית ארוכה אחת מתוך הנחיה אחת, הוא מנהל סבבים קצרים של שאלות. כל סבב נבנה מהתשובות האחרונות שלכם *ומההערות החופשיות שלכם*, שלעתים אומרות יותר מהאפשרות שבחרתם. החלטות מוצעות גם לרכיבים דומים כאשר יש בכך תועלת, והוא מחפש "ידע שלישי": שני חלקים שכבר קיימים אצלכם ויחד עושים דבר שאף אחד מהם לא עושה לבד. הוא זוכר את הטעם ואת כללי העיצוב שלכם בין מפגשים, ומסיים בתוכנית גל בגודל שאפשר לשחרר, עם סדר עבודה לפי תלויות, מסלולים מקבילים כשיש בהם תועלת ואימות מתאים לכל משימה.

[English](README.md)

*עיצוב ותכנון: אייל נוף. השימוש הראשון היה בהפיכת רכיבים חזקים אך מנותקים של תוכנת הפקת מוזיקה בדפדפן לאולפן אחד שאפשר לעבוד בו. ראו את [דוגמת המפגש](examples/creation-studio-run.md) באנגלית.*

## התקנה ושימוש

המתכנן־השותף הוא הרחבה למצב התכנון המובנה. תחילה מפעילים את מצב התכנון בסביבה, ואז מפעילים את המיומנות. בסביבת Claude Code משתמשים בקיצור `Shift+Tab` עד שמצב התכנון פעיל; בסביבת Codex משתמשים בבקרת התכנון או בפקודה `/plan` כאשר היא זמינה. רק לאחר אישור התוכנית עוברים ליישום בתהליך הרגיל של הסביבה.

הגרסה לתוסף של Claude נשארת זמינה דרך השוק הקיים:

<div dir="ltr">

```text
/plugin marketplace add Architect-of-knowledge/co-planner
/plugin install co-planner@architect-of-knowledge
/co-planner --guided --lang he תכנן איתי יישום להזמנת פגישות
```

</div>

הגרסה החדשה ל־Codex נמצאת בתיקייה `codex/skills/co-planner` שבמאגר. העתיקו אותה לתיקייה `~/.agents/skills/co-planner` לשימוש אישי, או לתיקייה `.agents/skills/co-planner` בפרויקט היעד. אם כבר קיימת התקנה, בדקו את ההבדלים לפני החלפה. ההפעלה נעשית באמצעות `$co-planner` בשיחה.

הגרסה שבשוק עשויה לפגר אחרי העותק המקומי. להוראות טעינה מקומית ראו את [מדריך השימוש בעברית](how-to-use.he.md) למשתמשים מתחילים, רגילים ומומחים.

## סגנונות התכנון

- הסגנון המסתגל הוא ברירת המחדל: עומק החקירה נקבע לפי אי־הוודאות וההשפעה.
- הסגנון `--style explore` מרחיב את בחינת החלופות לפני צמצום ההיקף.
- הסגנון `--style converge` מתמקד בחסמים ובתוצאה השימושית הקטנה ביותר.
- המצב `quick` מגביל את השיחה לשני סבבי שאלות ולמסלול אחד, גם אם נבחרה חקירה מעמיקה.
- ההדרכה `--guided` מציפה שאלות חשובות שקל לפספס, באמצעות תרחישים מוחשיים, הסבר והמלצה.
- המצב `--efficient` משפר תדריכים ואימות ומתאים עובדים זמינים למשימות; הוא אינו מחליף את מודל השיחה.

ההדרכה מוצעת אוטומטית כשיש בה צורך. אפשר לבקש אותה במפורש, לשנות סגנון במהלך השיחה או לדחות את ההצעה בלי לעצור את התכנון.

## איך נראה מפגש

ראשית מבררים את התוצאה הרצויה ואת המגבלות, ובפרויקט קיים בודקים את הקוד הרלוונטי. בפרויקט חדש מסתמכים על מטרות, דוגמאות והנחות מסומנות. המפה היא כלי עזר בלבד: היעדר מצב משותף שזוהה אינו הוכחה להעברה שבורה, כי ייתכנו חיבורים דרך נתיבים, אירועים או שרת.

הצעות לשיפור כוללות תועלת, ראיות, מאמץ, חסרונות ודרך אימות. ההחלטות נבנות מהתשובות ומההערות שלכם. הפצה למשפחת רכיבים היא הצעה עם חריגים מוצדקים, ורעיונות נוספים אינם נכנסים להיקף בלי אישור.

התוכנית מוכנה כאשר התוצאה, ההיקף, ההחלטות החוסמות, התלויות ותנאי האימות ברורים. אין אחוז תיאום מומצא. כל משימה קשורה לתוצאה שהוסכמה, עם תנאי השלמה ובדיקה מתאימה. מסלולים מקבילים נבחרים רק כשהתלויות מאפשרות זאת.

## ניהול הקשר וזיכרון

ברירת המחדל מנהלת אזורים מסומנים קטנים בקובץ ההוראות של הסביבה, למשל `CLAUDE.md` או `AGENTS.md` בפרויקט. טקסט קיים מחוץ לאזורים האלה נשמר. קובץ מצב קיים מקבל עדיפות; ברירת המחדל היא `.co-planner/handoff.md` בפרויקט.

מסמך המצב מכיל יעד, קישור לתוכנית, החלטות, התקדמות, תוצאות בדיקות והפעולה הבאה. העדפות, כללים ותובנות נשמרים בקובצי נושא ונקראים לפי הצורך. העדכונים נעשים באבני דרך ובמעברים, ולא אחרי כל פעולה.

במצב תכנון לא נכתבים קובצי זיכרון בניגוד להגבלות הסביבה. העדכונים ממתינים לשלב היישום המאושר. בזיכרון האוטומטי של Claude נוסף רק מצביע קטן כאשר הסביבה חושפת מיקום שניתן לכתוב אליו. הזיכרון הפנימי של Codex נשאר בניהול הסביבה עצמה.

להשבתת הכתיבה המנוהלת הגדירו `"contextManagement": "off"` בקובץ התצורה. הבודק מדווח על גודל ושגיאות קישור, ולא על חיסכון מובטח באסימונים. פירוט האפשרויות נמצא ב[מסמך התצורה](plugins/co-planner/skills/co-planner/references/config.md) באנגלית.

## עברית וכלי עזר

הבקשה בעברית בוחרת עברית כברירת מחדל, ואפשר לקבוע שפה באמצעות `--lang he` בפקודה. קבצים חדשים נעטפים מימין לשמאל, קוד נשאר משמאל לימין, ואין שינוי עיצוב כפוי בתוכן קיים של המשתמש. ראו את [כללי העברית](plugins/co-planner/skills/co-planner/references/he.md) המפורטים.

כלי המפה ובדיקת ההקשר דורשים Node.js בגרסה 18 ומעלה, ללא תלויות נוספות. מתאם מפה מקומי מופעל רק אחרי בדיקתו ובצירוף `--adapter` לפקודה. כשאין כלי מתאים, אפשר לבצע חקירה ידנית ותכנון סדרתי.
